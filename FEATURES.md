# Pathvector — Feature Inventory

Fork: `XodoTechnology/pathvector` (upstream: `natesales/pathvector`). Go CLI + config-generation
engine that turns a single declarative YAML (`pathvector.yml`) into a complete BIRD routing
daemon configuration, validates it, and applies it live over BIRD's unix control socket.

## CLI Commands (`cmd/`)

| Command | What it does |
|---|---|
| `generate` (`gen`, `g`) | Full pipeline: parse config → templates → per-peer `.conf` files → `bird -p` validation → move into `bird-directory` → `configure` over socket. `--withdraw` stuns all announcements. |
| `status` (`s`) | Tabular protocol status from `show protocols all` via socket; maps machine protocol names back to peer names/tags via `protocols.json`; `--bgp`, `--filter <tag>` filtering. |
| `protocol` (`p`, `protocols`) | `restart`/`reload`/`enable`/`disable` a protocol (or `all`) over the BIRD socket; `-m` sets the disable message. |
| `birdsh` | Interactive/single-shot BIRD shell over the unix socket. |
| `config` | Dumps config with version banner, BIRD version, uname; `--sanitize` redacts keys (password, peeringdb-api-key) via logknife. |
| `dump` | Peer table (name, ASN, local-pref, prepends, neighbors, template, options) or full resolved YAML (`--yaml`). |
| `match <ASN>` | Finds common IXPs between local ASN and a peer ASN via PeeringDB; `-y` emits ready-to-paste YAML peer stubs. |
| `serve` | Management API daemon (see below). `--listen` overrides `api-listen`. |
| `report` | One-shot session-state report — prints JSON, or `--post` to `report-url`. |
| `optimizer` | Long-running probe daemon (see below). |
| `docs` | Hidden; regenerates config-field docs from struct tags (autodoc). |
| `version` | Version/commit/date banner. |

Global flags: `--config`, `--lock`, `--verbose`, `--trace`, `--dry-run`, `--no-configure`.

## Configuration Model (`pkg/config`)

**Global (`Config`)**: ASN, router-id, announced prefixes, source4/6, hostname, PeeringDB
(URL, API key, cache, timeout — supports a local pdb cache like `pdb-cache.xodo.net`),
IRR server + bgpq4 args, RTR server (RPKI), blocklists (inline + URLs + files),
origin/local/import/export communities, kernel routing table options (learn, export,
statics, SRD community filtering, per-AF accept/reject of BIRD protocols), default-route
behavior, bogon lists (v4/v6 prefixes + ASNs), transit-ASN list (Peerlock-lite),
`authorized-providers` (ASPA map), `stun`/`no-announce`/`no-accept` kill switches,
keep-filtered, merge-paths (ECMP), web-ui-file, keepalived-config path.

**Per-peer (`Peer`, ~100 options)**: templates, description, tags, disabled,
import/export switches, ASN + neighbor list, prepends / prepend-path / clear-path,
local-pref (+ per-AF overrides + as-prefs/community-prefs maps), multihop, listen
addresses, local-asn override, local/neighbor ports, passive, direct, next-hop-self
(eBGP/iBGP variants), BFD, MD5 password, rs-client, rr-client, remove-private-asns,
mp-unicast-46 (dual AF on one session), allow-local-as, add-path tx/rx, import/export
next-hop rewriting, confederation (+member), TTL security (GTSM), interpret-communities,
default-local-pref, advertise-hostname, disable-after-error, prefer-older-routes,
IRR accept-child-prefixes, community lists (add-on-import/export, announce, remove,
remove-all), as-set (+ members, + auto from PeeringDB/IRR), import/receive/export
prefix limits with trip actions, enforce-first-as, enforce/force-peer-nexthop,
blackhole in/out + allow-blackhole-community, all filter families (IRR, RPKI,
strict-RPKI, max-prefix, bogon routes/ASNs, transit-ASNs, prefix-length,
never-via-route-servers, as-set, ASPA, blocklist), transit-lock, dont-announce /
only-announce, prefix-communities, RFC 9234 roles (+require-roles), graceful-shutdown
honoring, announce-default/originated/all, per-peer custom filter injection points
(`session-global`, `pre-import-filter`, `post-import-filter`, `pre-import-accept`,
`pre-export`, `pre-export-final` — all supporting `<pathvector.field>` substitution),
optimizer probe sources + optimize-inbound, `gateway` (direct|recursive nexthop
resolution), `interface` (link-local sessions), `bgp-med` (default MED),
`comments` (rendered as a header block in the generated peer file).

**Config fragments (`include:`)**: glob patterns resolved relative to the config
file's directory merge `peers`, `templates`, `vrrp`, `bfd`, `mrt` maps into the
base config; duplicate keys are an error.

**Generated-file banner (`show-warning-message`, default true)**: emits an
"AUTOGENERATED BY PATHVECTOR — DO NOT EDIT" header plus an update timestamp in
`bird.conf`, per-peer configs, and the keepalived file.

**API/reporting (`Config`)**: `api-listen` (host:port or `unix:///path`),
`api-key`, `api-sessions-dir`, `report-url`/`report-key`/`report-interval`/
`report-router`/`report-prefix-cap` for pushing state to XodoPanel.

**Auxiliary**: VRRP instances (renders keepalived.conf), BFD instances, MRT dump
instances, kernel statics, optimizer settings, plugin config map.

## Generation Pipeline (`pkg/process`)

1. Strict YAML parse + validator tags + `default:` struct-tag defaulting
   (reflection-driven; every peer field gets its documented default).
2. Template inheritance — peers copy any field left unset from their named template.
3. Community sorting (standard vs large), prefix family splitting, role validation.
4. Optional enrichment: PeeringDB query (auto import limits / as-set), bgpq4 IRR
   prefix sets, auto as-set members, NVRS list.
5. Renders embedded `global.tmpl` + `peer.tmpl` per neighbor per address family;
   per-peer files `AS<asn>_<name>.conf` into a cache dir; also emits
   `vrrp.tmpl` (keepalived) and `ui.tmpl` (standalone HTML status page).
6. `bird -c bird.conf -p` parse validation with friendlier error extraction.
7. Atomic-ish apply: wipe old `AS*.conf`, move cache → `bird-directory`, `configure`.

## Filtering & Security Features

- Bogon prefix sets (full v4/v6 bogon lists built in) + bogon ASN path filter.
- RPKI via RTR (`rtr-server`), invalid reject or strict valid-only.
- IRR prefix filtering via bgpq4 with `-S source` expansion and RPKI-aware source lists.
- ASPA (`authorized-providers`, `filter-aspa`), Peerlock-lite (`filter-transit-asns`),
  transit-lock allowlist, never-via-route-servers (PeeringDB NVRS flag).
- Global blocklist from inline lists, files, and remote URLs.
- Per-peer max prefix limits at three stages (receive/import/export) with configurable
  trip action; max-prefix-length sanity filter; enforce first-AS and peer next-hop.
- **`action-communities` + `pop-id`**: renders an ISP-style community library into the
  global config, keyed on the config's own ASN — action communities (`ASN:911:asn`
  no-export-to-AS, `739:ix` no-announce-at-IX, `711-713`/`72x`/`73x` prepend
  general/per-AS/per-IX) and informational marking (`411` source, `412` IX,
  `414` upstream, `511` RPKI state), plus composed `import_communitys`/
  `export_communitys` pipelines callable from `pre-export`/`post-import-filter`
  hooks. `pop-id` emits `define pop_id = N;` for per-site tagging.

## Route Optimizer (`pkg/optimizer`)

Long-running daemon: pings configured targets from per-peer source addresses
(ICMP or UDP), keeps a rolling result cache, and when loss/latency exceeds thresholds
rewrites the `# pathvector:localpref` marker in that peer's generated file
(local-pref modifier), revalidates, and reconfigures BIRD. Optional alert script hook
and `exit-on-cache-full` mode.

## BIRD Integration (`pkg/bird`)

Unix-socket client (length-prefixed line protocol, version check ≥ 2.0.7), config
validation with contextual error display, `configure` reconfigure, protocol/route/
BGP-state parsers used by `status`, and a post-render whitespace reformatter.

## Extensibility

- **Plugins** (`pkg/plugin`): compile-time Go plugin registry — plugins can mutate the
  loaded config (`Modify`) and add cobra subcommands; built via `plugin-generate.py`
  + `plugin.cfg`.
- **Template funcs** (`pkg/templating`): `BirdSet`, `BirdASSet`, deref helpers,
  `UniqueProtocolName`, `Contains`, `SplitFirst`, map iteration helpers, etc.
- **Autodoc** (`pkg/autodoc`): generates the configuration reference from struct tags.
- **Integrations**: docs exist for Fastnetmon; `vendorbuild/` has sample vendor
  configs (Arista/Cisco/Juniper/Mikrotik); `distrib/` packaging scripts.
- **Web UI file**: `web-ui-file` renders a self-contained HTML session-status page.

## Management API (`pkg/api`, `pathvector serve`)

JSON over HTTP on a unix socket (`unix:///path`, 0660) or TCP (`api-key` bearer
required on TCP; `X-API-Key`/`Authorization: Bearer`/`?key=` accepted). All
mutations are serialized, validated via the normal load → render → `bird -p` →
`configure` pipeline, and rolled back on failure. `?dry_run=1` on any mutation
validates without applying. BIRD socket commands carry a deadline
(`bird-timeout`, default 60s). `GET /v1/status` includes `config_sha256` +
`last_apply`/`last_apply_error` for drift detection.

| Endpoint | Purpose |
|---|---|
| `GET /v1/health` `GET /v1/version` | liveness, version incl. BIRD version |
| `GET /v1/status` | parsed `show protocols all` as JSON |
| `GET /v1/sessions` | per-peer aggregated session state + route counts |
| `GET /v1/sessions/{name}` | session detail incl. received/filtered prefix lists + AS paths |
| `PUT /v1/sessions/{name}` | create/replace session; JSON body uses the peer YAML field names |
| `PATCH /v1/sessions/{name}` | merge fields; `null` deletes a key |
| `POST /v1/sessions/{name}/enable|disable` | toggle `disabled` |
| `DELETE /v1/sessions/{name}` | remove session + re-apply |
| `GET /v1/sessions/{name}/config` | stored fragment, secrets redacted |
| `POST /v1/reconcile` | desired-state sync: `{sessions:{…}, prune, rules:[…]}` — one apply for any number of changes, returns created/updated/deleted/unchanged diff |
| `GET/PUT/DELETE /v1/rules` | global `prefix-rules` set (per-prefix policy: reject/blackhole/prepend, no-transit/no-peers/no-export panel actions, template-targeted) |
| `GET /v1/config` | config YAML with sensitive keys redacted |
| `PUT /v1/config` | whole-config push (staged → validated → swapped → applied) |
| `POST /v1/generate` | re-render + apply current config |
| `POST /v1/bird` | BIRD socket passthrough, `show *` commands only |
| `POST /v1/report` | collect report JSON; `?post=1` pushes it to `report-url` |

Sessions created via the API are persisted as one YAML fragment per session in
`api-sessions-dir` (default `sessions.d/` next to the config file), merged via
`include:` — so CLI `generate` sees them too, and the panel owns them entirely.

## XodoPanel Touchpoints

- XodoPanel renders a complete `pathvector.yml` from its DB at
  `GET /api/pathvector.yml?key=…` (templates upstream/routeserver/peer/downstream,
  peers from `bgp_sessions`, per-prefix customer rules rendered into template
  `pre-export` filters). Routers cron-scrape it, run `pathvector generate`, reload BIRD.
- Routers push live state to `POST /api/v1/bgp/report` (session state, uptime,
  accepted/filtered/sent prefix lists + AS paths) → `bgp_observed_prefixes`,
  `bgp_sessions.live_state`, `bgp_routers` rollup, webhook alerts on up/down flaps.
